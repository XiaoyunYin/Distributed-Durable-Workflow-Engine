# K6 G2b external evidence and quiet

The checker retains the [G2a paired database exports](k6-g2a-checker.md) and adds the sources below. A clean engineering verdict exits 3. The partial labels use `predicate_partial:G2b` or `slice_not_implemented:G2b`. A registered predicate with an observed contradiction reports `covered/fail` and sets episode safety to FAIL.

## Public files

| Path | Required arms | Contents |
| --- | --- | --- |
| `witness/inventory.json` | All | Kubernetes list cursor and ordered watch updates, container UID/start/restart observations, authenticated process registrations and independently observed deaths. |
| `witness/<session>.jsonl` | All, once per independently rostered session | Receiver header, entry ACK records, finish/abort, worker send/receive/close/timeout, and separate idle probe and renewal kinds. Every session needs a persisted ledger, including a ledger containing only its header row. |
| `witness/effect-ingress.jsonl` | Effect | Each observed relay copy and the direct authenticated allocator channel. Rows bind method, message/request/key and grant digests, intent, resource, worker-facing and sink-side connection bindings, exact request and response entity digests and lengths, relay wire digest and length, response disposition and application ID. |
| `auth/decisions.jsonl` | Effect | Authenticated adapter observations of pending reads, approvals, rejections and successful replays. The adapter commits the public observation before replying. The engine intent supplies the issued grant digest when issuance follows approval. |
| `broker/positions.jsonl` | All | Cluster and group identities, group generation, members and assignments, topic and topic ID, partition, low/end offsets, optional committed offset, and observation brackets. The collector brackets the reads with group descriptions and binds classic-group generations to an independent coordinator witness. |
| `witness/topology.json` | PURE | The rendered component inventory and independent Deployment, Service, database, relay and ingress-journal observations. The manifest commits to the canonical rendered component array. |
| `samples/external.json` | All | The checker observer's ordered quiet, pre-cut, post-cut and export samples, with DB activity-sensitive digests and per-source cumulative positions. Samples bind the paired cut generation. |

The index pins full file bytes. Roster and topology objects contain `header`, `rows` and `seal`. Every JSONL file has a header line, zero or more numbered rows and a final seal line. All sources commit episode, namespace, reset and barrier identities. Each seal carries the observed attempted, written and error counts, sequence range, canonical row bytes, digest and observation time. A death certificate binds the exact runtime identity to the receiver's final persisted sequence and digest. Live snapshots may carry checkpoints while collection runs. The selected export requires terminal seals or receiver-final worker seals with corroborated death. A declared session is required even when its ledger and index entry are both absent.

The checker joins starts to engine attempts and committed claim identities using invocation, attempt, claimant, request identity and the SHA-256 of the exact claim token bytes. A pre-entry death must be independently observed within the claim's runtime interval. On effect arms every worker send closes through a relay copy and worker disposition. The checker matches sink calls by individual connection and verifies applications, allocations, lookup misses, decisions and request bindings in reverse. A timeout alone cannot establish a withheld committed reply. The direct allocator has its own authenticated connection evidence and joins to the intent and allocation.

## Live acquisition

Set `external_dir` in the private checker configuration to the directory published by `dur053-k6-collect PRIVATE_CONFIG`. The collector writes immutable `frame-N` directories and atomically advances `current` after syncing the files. Each frame includes the complete retained public prefixes. A directory of frozen sources is usable for decoder fixtures. Missing evidence still produces source-specific offline failures. The existing live mode exports and verifies the same indexed public bytes as offline.

The collector's closed configuration carries the public manifest and `output`, `context`, `worker_selector`, `worker_container`, `receiver`, `registrations`, `brokers`, `group`, `topics`, `members`, `rendered`, `platform`, `relay_journal`, `relay_peer`, `sink_peer`, `allocator`, `decisions` and `fence`. Supply empty strings for paths outside the arm. `topics` maps the observed topic names to topic IDs. `members` points to a versioned coordinator observation with `generation` and a `members` map from member ID to generation.

G2c starts the Kubernetes list/watch before launching workers and retains independent pod-bound worker-control registrations. The registrations file contains `session` and `identity` pairs. The collector fetches the receiver-owned ledger for each registered session, retains extras for the reverse join, and certifies the last persisted prefix following a kubelet termination observation. The worker's opt-in `DUR053_K6_G_WORKER_DIR` must be durable and mounted as the collector receiver's `witness/` directory. Supply the worker's observed container ID, restart count and start time, along with the bound episode, reset and barrier environment. The worker fsyncs the public start before entering the payload. G2c can use the existing Kafka coordinator callbacks as the generation witness and independently describes broker offsets and membership.

Use the host receiver journal from `dur053-k6-witness`, the decision adapter's optional `Evidence` configuration, and the allocator's `DUR053_K6_G_ALLOCATOR_FILE` on effect arms. These producers hash claim and grant tokens before encoding and retain digests and lengths for wire equality. The relay collector projects its sequence-checked receiver journal into completed copies. The PURE collector lists the namespace's actual Deployments and Services and reads a separately acquired database, journal and relay inventory. G2c owns the reset provisioning record and the worker, relay, decision and allocator admission shutdown that the reset-bound fence attests. Retain the raw receiver capture, coordinator observations and provisioning records with the job evidence.

The collector opens no PostgreSQL sessions. The checker retains one engine and one sink connection at most and uses those same connections for the quiet samples. The worker clock for its ledger is monotonic anchored to process startup. Group sampling observes versions between reads and the recorded membership changes. G3 still owns the fault-specific membership and redelivery predicates and must account for gaps between broker observations.

## Quiet and local validation

Quiet starts after arrivals close, any confirmed removal, terminal durable workflow state and closed worker exchanges. The observer polls the required external sources and the DBs. An activity change resets the 30-second interval. Regressions, source gaps, uncorroborated source replacement and stale observations fail completeness. Watch progress, idle probes and lease renewals keep their own monotone digest positions. A change between the DB cuts discards the pair and starts another generation within the original deadline. Offline verifies the recorded prefixes, sample freshness and duration, selected generation, both DB-local watermarks and the final external seals.

The PostgreSQL fixtures run two locally isolated instances in effect mode and compare live and offline stdout byte for byte. The network-free fixtures reseal source edits and exercise session closure, delivery closure, PURE topology, missing proof and the quiet interval. The existing PostgreSQL CI job runs the service-backed fixtures. G2c supplies deployed collection, a deliberate mid-cut write and retake, and the hosted idle-cluster pair.

# DUR-053 K6 Phase G — independent checker and evidence export

Round 420 design for review, based on `41507a8`. G delivers a Go checker that can explain its verdict for one independently reset episode using only the public evidence bytes. H owns campaign dispatch, archive intake, admission and release verification. All G runs are engineering evidence (`measurement_claim=false`, `charged_seconds=0`). The pre-data authorities are [Ruling 3 and the cell tables](k6-design.md), the [registry](k6-registry-v1.json) and [protocol v2, including B.2 and B.8](protocol-v2.md).

## Entry points and trust boundary

Add explicit, mutually exclusive `dur049-checker -k6-live-v1 <private-config>` and `-k6-offline-v1 <episode-dir>`. Live takes local credential descriptors, a sealed plan and observed source locations, performs the barrier, writes the public bundle, and evaluates the rows it read. Offline opens the indexed bundle with no DB, broker, cluster or network access. Both feed one typed, strict v1 decoder and one deterministic evaluator under `internal/invariants`. Reject mixed selectors, workflow-ID subsets, unknown versions, duplicate keys, unknown fields and trailing input. Emit deterministic UTF-8 JSON and nonzero exit on failed or incomplete verification. Keep acquisition diagnostics separate from the comparable result. Compare legacy live, snapshot, campaign, clock and K4 lifecycle invocations against baseline stdout, stderr and exit codes, including failures. Preserve legacy encoders and flag dispatch.

- Factor checker-owned rules behind `Check` (`checker.go:189`) for history edges/continuity, submission uniqueness, result/attempt ownership, transport obligations and M4 proposal/scope/dispatch. Supply row IDs to each rule. The transport path calls `state.EventTopicFor` and uses state enums. Give K6 a frozen checker-owned event/topic/disposition contract and test it against public protocol fixtures. Keep the verdict package's dependency closure free of production state, engine, sink validators and Python smoke joins. Isolate DB I/O (pgx) and legacy adapters from that package. Use the persisted K6 contract for legitimate duplicate request IDs on distinct deliveries.
- Adapt R228 whole-namespace counts, history-length/final-revision reconciliation and the two-way arrival and invocation joins from `campaign.go`. Its `PureCoverage` at line 119 supplies the scope of the five base labels. Its all-offered-success prerequisite, raw-token witness, preset outcomes and blanket relabel-on-error do not model K6. Reuse the strict identity, acknowledged-start, death, committed lease/receipt order and stale-versus-evidence-only rules from `lifecycle.go`. K4's report is a different schema. Extend `m5.go:110`'s boundary/object joins with actual peer/process identity, fsynced ACK, broker reads and cell-specific independent confirmation/removal. A fixture trace alone cannot confirm an intervention.
- The existing `snapshot.go:95` attempt projection contains a clear claim token, the effect projection around line 101 reads legacy effects in the engine database, and the generic raw-table loop around line 192 serializes complete unsanitized rows. Approvals also copy the grant token. Introduce a separate public v1 loader with explicit typed column projections at the read boundary, redacted identities and an independent sink reader. Derive projections from those same public rows. Legacy `Trace.Snapshot`, even with its top-level token fields cleared, is unsuitable for publication.

3. There is no cross-database atomic snapshot. Discard a raced cut as a candidate for success, retain its reason and retake **both** cuts after renewed quiet within the original deadline. Historical offline replay uses the recorded deadline and seal time.

Run each through the normal live adapter on isolated databases/producer streams and through the offline adapter on a separately corrupted immutable bundle. For DB constraints that prohibit a corrupt stored state, inject the bad row at the live relation-reader boundary under test and identify that substitution. For semantic faults regenerate dependent file counts/hashes and keep producer summaries PASS so decoding or a stale checksum cannot kill the mutant accidentally. Require the stated reason and witness ID, legacy output equality and a clean positive twin. For integrity faults keep the original independently sealed index/count. Exercise each source deletion even when it originally held zero rows.

## Censoring, metrics and report

Create a row at population entry with identity, start/source clock, endpoint type, event time (nullable), last confirmed observation, cut/deadline, elapsed lower bound, justified upper bound or null, censor reason and witness IDs. Preserve unresolved, abandoned, canceled, unexecuted and inapplicable strata separately. A valid death observation can bound a busy interval with no finish. An unfinished recovery at timeout remains right-censored and fails the run/SLO for incomplete accepted work. A corrupt/truncated archive, absent required sample or broken seal is missing evidence and fails completeness. Never synthesize a finish at export, drop a slow row, or rehabilitate the run from a later snapshot. In a sealed complete interval, zero observed events is distinguishable from unavailable observations.

Reconcile warmup and measured arrivals at frozen 0.5r. Warm for 120 s, target in-flight work or an ACKed boundary within a further 2L, start measurement at intervention (immediately after warmup for controls). Keep warmup work active for safety and affected-work recovery. Only measured scheduled arrivals enter latency. W=max(180 s,60/(0.5r))=180 s for both short and medium. Use frozen L of 2.854 s short and 52.041 s medium. Tag active-fault, post-confirmed-removal and steady control windows, preserve extension, hold and recovery intervals and every scheduled ID.

## Registered SLI and exporter projection

“SLO attainment requires at least 99% of accepted workflows to succeed within frozen `L` from scheduled arrival and zero incomplete accepted work at reconciliation.” The short freeze records `"L": 2.854` seconds. The one error budget is **1%**. For a deadline window, attainment = on-time successes / accepted identities whose scheduled arrival + L is in the window and has passed. Publish the whole episode's counts once every deadline has passed, plus the independent incomplete count at closeout. Zero eligible events gives an undefined ratio. Failed, canceled, late or still-running eligible work consumes budget. If all eligible work stalls, every newly matured admission is bad even while the terminal count is flat. [Registered objective, lines 107–113 and 151–155](../k8s-recovery/protocol-v2.md) · [Short freeze, lines 4579–4583](../k8s-recovery/k3-pilot-v1/freeze.json)

Before sending, the harness installs a sealed J-only schedule relation `j2_monitor.j3_plan(namespace, submission_key, scheduled_ns)` keyed by (namespace, submission_key). Store integer UTC epoch nanoseconds derived from the same origin and exact monotonic offsets used by the sender. Bind the namespace in the one-row installer-owned scope. Set `j3_clock.u_ns` (one row) to the setup DB clock-bracket width. After the run replay using the larger of setup/closing widths. Require valid enclosing brackets, schedule/journal/namespace identity equality and identical live vs replay classifications at sampled boundaries, or mark the result invalid. Retain raw latencies and sensitivity to clock width. The durable timestamp is the committed final revision's history time, written inside its transaction. [Clock convention, protocol-v2 lines 970–989](../k8s-recovery/protocol-v2.md) · [Schedule and history join, j2_offline.py lines 74–109,174–196](../../../scripts/j2_offline.py)

Register the following body for a J-only SQL projection in the exporter. One statement snapshot per sample. Window membership is by **deadline** in (t−W, t], including exact deadline equality at the right edge. `all` is cumulative. Return gauges for eligible and bad, and the sample time, with only fixed window and target labels. Never apply counter-rate functions to these gauges. The admission witness is a committed namespace workflow row, including a commit whose HTTP acknowledgement was lost. A separate integrity check rejects foreign-to-plan keys *inside* the target namespace, missing acknowledged rows, duplicate plan keys and broken terminal history. No inner join to a success table may remove an admission. Sources for schema and grants are [durable state migration, lines 13–34,155–171](../../../migrations/000002_durable_state.up.sql) and [monitor.sql, lines 1–24,44–48](../load-envelope/exporter/monitor.sql).

```sql
WITH clock AS (
    SELECT extract(epoch FROM statement_timestamp()) * 1000000000 AS t, u_ns
    FROM j2_monitor.j3_clock
), cohort AS (
    SELECT p.scheduled_ns + 2854000000 AS deadline_ns,
           w.state = 'SUCCEEDED' AND h.new_state = 'SUCCEEDED'
             AND extract(epoch FROM h.created_at) * 1000000000 + c.u_ns
                 <= p.scheduled_ns + 2854000000 AS on_time
    FROM j2_monitor.scope s
    JOIN engine.workflow_executions w ON w.namespace = s.namespace
    JOIN j2_monitor.j3_plan p
      ON (p.namespace, p.submission_key) = (w.namespace, w.submission_key)
    CROSS JOIN clock c
    LEFT JOIN engine.transition_history h
      ON (h.workflow_id, h.revision) = (w.workflow_id, w.revision)
), windows(label, width_ns) AS (
    VALUES ('2m', 120000000000::bigint), ('10m', 600000000000::bigint),
           ('all', NULL::bigint)
)
SELECT v.label, c.t, count(q.deadline_ns) AS eligible,
       count(q.deadline_ns) FILTER (WHERE q.on_time IS NOT TRUE) AS bad
FROM windows v CROSS JOIN clock c
LEFT JOIN cohort q ON q.deadline_ns <= c.t
    AND (v.width_ns IS NULL OR q.deadline_ns > c.t - v.width_ns)
GROUP BY v.label, c.t
```

## Three alert rules

All rules select the exact expected campaign and workflow namespace from the provisioned manifest, including on `up` via static target labels. Evaluate every **5 s** (J3, bounds transition timing at modest cost), scrape every **1 s**. Define valid input as one matching successful scrape, `up == 1`, successful SQL and demand reads, both source ages and last scrape age in [0,5] s, and a complete, coherent set of required fields from that cycle. Use J2's 5 s stale limit. An independently provisioned expected-target series exists even when service discovery drops the target. Invalid includes stale cached data, missing series, absent target and query failure with HTTP 200. Emit no replacement zeros. [J2 overlay, lines 119–126](../../../scripts/j2_overlay.py) · [J2 freshness, main.go lines 47–58](../load-envelope/exporter/main.go)

| Rule | Fire on the first qualifying evaluation | Clear on a qualifying evaluation |
| --- | --- | --- |
| OldestClaimable | Valid, claimable count > 0 and demand age **> 28.540 s**. J3 sets **10 × frozen L** so a sustained queue is visible well inside the outage while a single late workflow cannot cross the age threshold immediately. | Valid count = 0 or valid age ≤ 28.540 s. |
| DeadlineBudgetBurn | For **both** W = 10 min and 2 min, require eligible(W) ≥ **100** and (bad(W) / eligible(W)) / 0.01 **> 14.4**. J3 uses 100 per window so a single miss consumes at most 1% of that window. Exact equality to the burn threshold stays quiet. | Valid, sufficient volume in both windows and at least one burn ≤ 14.4. Keep offering A through recovery so a falling denominator cannot establish clearance. |
| ScrapeAbsent | Expected target minus valid input, continuously **5 s**. One evaluation of debounce distinguishes a transient read from sustained loss. | First complete fresh sample evaluated after restoration. Retain separate demand/SQL/scrape error diagnostics. |

The 10 min confirmation window and 2 min recent window scale down the usual 1 h / 5 min paging pair for a single hosted job. Both retain the 14.4× multiplier (14.4% bad with this objective). Under a complete stall at A the long window crosses after approximately 86.4 s of matured bad deadlines and the short after 17.28 s. These are crossing estimates under steady admissions. They do not imply a monthly budget-spend claim. Canonical D036:1741–1749 and [Google SRE Workbook, chapter 5, table 5-8](https://sre.google/workbook/alerting-on-slos/#multiwindow-multi-burn-rate-alerts).

For each domain rule, implement **fire predicate OR (previously firing AND no valid clear predicate)**, keyed only by campaign, namespace and rule. For example, normalize the previous evaluation's `ALERTS{alertname="DeadlineBudgetBurn",alertstate="firing"}` to campaign/namespace, then use `unless on(campaign,namespace)` against the positive clear vector. Comparisons used to form presence vectors filter false rows. Configure no pending duration for domain rules. This holds a firing incident across arbitrary missing samples or insufficient volume while a quiet incident stays quiet. A vanished series, Prometheus restart or synthetic receiver timeout cannot prove recovery. For the verdict also require uninterrupted rule evaluation, actual receiver transitions, fresh samples across the transition and independent durable progress since restore. A lapse in rule evaluation invalidates transition evidence. Rationale and control authority are canonical PLAN.md:3786–3788.

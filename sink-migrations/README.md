# DUR-053 K6 sink database

Apply `000001_k6_sink.up.sql` once as the setup administrator on a fresh database in the separate PostgreSQL instance. This numbered directory is independent of the engine migration sequence. The setup role provisions password authentication for the two initially NOLOGIN identities and limits their database CONNECT to the episode database. Keep `k6_sink_journal_owner` NOLOGIN. The exporter can read hashes and evidence rows through the grants in the migration. The service identity can write the resource and its associated records. The trigger owner can append to the journal.

Use `dur053-sink serve PRIVATE_CONFIG` with a private JSON file readable by the process owner. The configuration fields follow `serveConfig` in the command. The Go JSON encoding of the PEM fields is base64. Set the trusted episode worker namespace, ServiceAccount name and UID, Kubernetes API URL and CA, a separate TokenReview-only credential, distinct authorized SPIFFE URI SANs for the engine and ingress peers, and the trusted clock-probe uncertainty in microseconds. The service uses TLS 1.3 with verified client certificates. Use the `k6_sink_service` login for the sink DSN and the Phase B `k6_sink_grant_reader` login with verify-full TLS for the engine DSN. Supply the engine reader and sink DB credentials only through the private file.

All endpoints are POST. Submit the exact approved grant envelope described by `k6sink.Request` to `/v1/allocate`, `/v1/apply` or `/v1/lookup`. The engine presents its peer certificate without a bearer for allocation. The authenticated application ingress presents the unchanged worker token, with the sole audience `dur053-k6-sink`, for apply and lookup. Use a distinct request ID for a new operation or lookup and the same bytes and request ID for a transport retry. Allocation returns the issued resource fence. Apply and lookup return the stored receipt as JSON. A lookup without a receipt returns HTTP 404. Authentication and grant denials return HTTP 403 with a uniform response, and write conflicts return HTTP 409. TLS connection hashes derive from SHA-256 of the 32-byte TLS exporter with label `EXPORTER-dur053-k6-sink` and empty context.

Use `dur053-sink export PRIVATE_CONFIG` with a separate private file containing `ExportDSN` for the `k6_sink_exporter` login. The JSON snapshot comes from a single REPEATABLE READ, read-only transaction. Relation hashes cover the ordered JSON arrays as encoded by Go. Resource-state hashes cover the UTF-8 PostgreSQL jsonb text representation, and receipt canonical hashes use the K6 grant representation. Request bindings hash the operation, a NUL separator and the hex SHA-256 of the exact request bytes. The call table retains the SHA-256 of the exact bytes separately. Pre-validation rejects return before any sink ledger write.

Per-process database maxima are four for the sink, two for its engine grant reader and one for the exporter. These connections carry separate application names. Provision the instance and its remaining reserved role budgets at deployment.
